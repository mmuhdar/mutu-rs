# MutuRS — catatan proyek

- Spesifikasi: `.scratch/<fitur>/spec.md` + tiket di `issues/`. Istilah domain hanya dari `GLOSSARY.md` (tanpa sinonim). UI, pesan error, dan komentar kode memakai bahasa Indonesia; identifier domain memakai kata glosarium (`indikator`, `unitPelapor`, `pengukuran`, `capaian`), identifier teknis umum boleh bahasa Inggris.
- Stack: Next.js 16 (App Router) + Drizzle (`pg`) + PostgreSQL 17, pola dari `sistem-radiologi-digital`. Next 16 berbeda dari yang umum dikenal: baca `node_modules/next/dist/docs/` sebelum memakai API Next.
- Logika bisnis di `src/modules/<modul>/service.ts`. Setiap fungsi service menerima Pengguna yang sedang bertindak dan memeriksa peran + Unit di dalam service, bukan di halaman/action. Aturan murni bersama (konstanta, status, perhitungan) di `src/lib/`.
- Pengguna & sesi: service menerima `aktor: Pengguna | null` (tipe dari `src/modules/auth/service.ts`) dan memanggil `wajibPengguna(aktor)` lebih dulu; penolakan dilempar sebagai `ServiceError(status, pesan)` (`src/lib/errors.ts`), lalu server action mengubahnya menjadi `{ error }` untuk form lewat `hasilAtauError(janjiService)` (`src/lib/errors.ts`; halaman memakai `pesanAtau`). Isian form dibaca `teks(formData, nama)`, isian alamat halaman `teksAlamat(searchParams, nama)` (`src/lib/form.ts`). Lima peran = konstanta `PERAN`/`LABEL_PERAN` di `src/lib/peran.ts` (nilai `petugasInputData`, `kepalaUnit`, `komiteMutu`, `direktur`, `adminSistem`). Setiap halaman selain `/masuk` memanggil `requireUser()` (`src/server/sesi.ts`); action memakai `getSessionUser()` dan meneruskannya ke service. `src/proxy.ts` hanya penyaring awal (cookie ada/tidak). Tes mendapat aktor lewat `masuk(...)` lalu `penggunaDariToken(token)` atas Pengguna sungguhan yang dibuat lewat service Pengguna (`sebagai(peran, unitIds?)` di `tests/bantuan.ts`), bukan `{ ...admin, peran }`; Admin Sistem awal untuk tes = `config.adminAwal` (`adminSistem()`).
- Batasan peran di service: `wajibPeran(aktor, ["adminSistem", ...], pesan)` (`src/modules/auth/service.ts`) menggantikan `wajibPengguna` dan menolak peran lain dengan 403. Data master tidak pernah dihapus, hanya `aktif = false`; nama unik tanpa membedakan huruf besar/kecil = nama di-`trim()` di service + indeks unik `lower(nama)`, pelanggaran (`kodePg(e) === "23505"`, `src/lib/errors.ts`) menjadi 409. Pilihan Unit di formulir mana pun memakai `pilihanUnit(aktor)` (`src/modules/unit/service.ts`, hanya Unit aktif); `daftarUnit` = daftar kelola Admin Sistem (semua Unit + status).
- Unit milik Pengguna: tabel `pengguna_unit`, hanya untuk `PERAN_BER_UNIT` (`src/lib/peran.ts`: Petugas Input Data, Kepala Unit); service lain membaca Unit aktor dari `aktor.unitIds` (dimuat ulang tiap permintaan, bisa berisi Unit yang kini nonaktif). Aturan sandi baru (minimal 8 karakter) = `hashSandiBaru()` di auth service. Id dari form diperiksa dengan `apakahUuid()` (`src/lib/uuid.ts`) sebelum masuk query; yang bukan uuid = 404.
- Menu utama: tambah entri ke `MENU` di `src/app/layout.tsx`, dalam kelompok Data / Perbaikan / Pengaturan (`{ href, label, ikon, area, peran }`, ikon garis dari `src/app/ikon.tsx`, `area` = warna area halamannya); disaring per peran hanya untuk tampilan. Sidebar dan menu HP = `src/app/nav-samping.tsx`. Aturan tampilan per peran di halaman memakai helper dari service, bukan `peran === ...`: `bolehKelolaIndikator`, `bolehIsiPengukuran`/`bolehVerifikasi` (service Pengukuran), `melihatCapaianRs` (service Capaian, satu-satunya daftar peran yang melihat Capaian RS). Halaman yang ditolak service menampilkan pesan `ServiceError`-nya lewat `pesanAtau` (`src/app/pengukuran/status.tsx`; lihat `src/app/unit/page.tsx`), bukan halaman error.
- Gaya UI: halaman = server component yang memanggil service langsung untuk membaca; perubahan data lewat server action tipis (`actions.ts` di samping halaman, dipakai dengan `useActionState`). Tanpa `/api/*` untuk UI.
- Konfigurasi instalasi hanya dari environment lewat `src/lib/config.ts` (`DATABASE_URL`, `NAMA_RS`, `APP_TIMEZONE` bawaan `Asia/Makassar`, `ADMIN_USERNAME`/`ADMIN_PASSWORD` untuk Admin Sistem awal). Variabel baru: tambahkan ke `.env.example` (dengan penjelasan) dan `docker-compose.yml`. Root layout memanggil `await connection()` supaya nilai env tidak terbekukan saat `next build`.
- Bulan ditulis `"YYYY-MM"`. Bulan berjalan hanya dari `bulanBerjalan()` (`src/lib/bulan.ts`, ikut zona waktu konfigurasi), jangan dari `getMonth()`/jam server. Fungsi yang bergantung pada waktu menerima `sekarang = new Date()` opsional supaya bisa dites.
- Kolom bulan di database = `date` tanggal 1 (`mode: "string"`) + CHECK `extract(day from ...) = 1`; service menerima/mengembalikan `"YYYY-MM"` dan mengonversi dengan `keTanggal`/`dariTanggal`, validasi `bulanValid` (di service: `wajibBulan(bulan, pesan?)`, selain "YYYY-MM" ditolak 400; bulan yang belum berjalan ditolak `wajibBulanBerjalan(bulan, sekarang)`), tampilan `labelBulan` ("Oktober 2026"; `{ pendek: true }` = "Okt 2026", `{ tahun: false }` tanpa tahun, juga untuk sumbu grafik), semuanya di `src/lib/bulan.ts`. Nilai desimal (Target) = `numeric(..., { mode: "number" })`. Angka dari form: action mengubah koma desimal dan isian kosong menjadi `NaN` (bukan 0), service yang menolaknya.
- Indikator: konstanta `KELOMPOK` (`INM`, `IMP-RS`, `IMP-Unit`), `ARAH` (`makinTinggi`/`makinRendah`, tanda ≥/≤ = `TANDA_ARAH`), `FREKUENSI` (`bulanan`/`semesteran`) + labelnya di `src/lib/indikator.ts`; CHECK konstanta di skema lewat `salahSatu(kolom, daftar)`. Modul `src/modules/indikator/service.ts` (Komite Mutu + Admin Sistem mengelola, `bolehKelolaIndikator(aktor)` hanya untuk tampilan); Target = tabel riwayat `target` (unik per Indikator + bulan mulai). 13 INM = `src/modules/indikator/inm.ts` (dari `docs/research/inm-rumah-sakit.md` + profil PMK 30/2022), di-seed `buatInmAwal()` hanya untuk kode yang belum ada. Tes yang mengubah INM harus mengembalikannya; tes lain membuat IMP sendiri.
- Target berlaku: satu-satunya aturan = `targetPadaBulan(riwayat, bulan)` (`src/lib/indikator.ts`; berlaku mulai terbaru yang tidak lewat dari bulan itu, Target pertama berlaku mundur, jadi Target awal INM "2022-10" juga untuk arsip sebelumnya). Satu-satunya pembaca tabel `target` = `riwayatTarget(indikatorIds)` (service Indikator; dipakai `ambilIndikator`, `targetBerlaku`, dan modul Capaian). Service `targetBerlaku(aktor, indikatorId, bulan)` untuk satu bulan; untuk banyak bulan ambil riwayat sekali lalu panggil `targetPadaBulan`. `tetapkanTarget` = upsert per bulan mulai (bulan yang sama = koreksi nilai). Penguncian: field di `FIELD_CARA_HITUNG` (`src/lib/indikator.ts`) ditolak 409 oleh `ubahIndikator` bila berubah setelah ada Pengukuran (status apa pun; baris Indikator dikunci `for update`); `ambilIndikator(...).terkunci` untuk tampilan.
- Unit Pelapor: tabel `unit_pelapor` (periode bulan mulai s.d. bulan berhenti, **keduanya termasuk**; berhenti null = masih berlangsung), dikelola di service Indikator (`tambahUnitPelapor`, `akhiriUnitPelapor`, `hapusUnitPelapor`). Siapa yang wajib melapor pada bulan M hanya dari `unitPelaporAktif(aktor, indikatorId, bulan)` (aturan periode satu-satunya = `bersinggungan()` di service itu); Unit yang kini nonaktif tetap terhitung selama periodenya (`unitAktif: false`), jadi isian yang mensyaratkan Unit aktif memeriksanya sendiri. Tumpang tindih (Indikator + Unit sama, atau Unit mana pun untuk IMP-Unit) dicek di service dengan baris Indikator dikunci `for("update")`; `hapusUnitPelapor` juga menolak periode yang sudah punya Pengukuran, dan `akhiriUnitPelapor` menolak bulan berhenti sebelum Pengukuran terakhir (status apa pun) dalam periodenya, serta bulan berhenti ≥ bulan berjalan untuk Unit nonaktif (baris Unit dikunci `for share` sebelum baris Indikator). `aturAktifUnit` menolak menonaktifkan Unit yang masih Unit Pelapor pada bulan berjalan atau sesudahnya (`bersinggungan(bulanBerjalan, null)`; baris Unit dikunci `for update`, `tambahUnitPelapor` menguncinya `for share`). Query yang menggabungkan `unit_pelapor` dengan tabel lain memakai `bersinggungan(mulai, berhenti)` yang diekspor service Indikator, bukan aturan periode sendiri.
- Pengukuran: `src/modules/pengukuran/service.ts`; `STATUS_PENGUKURAN`/`LABEL_STATUS_PENGUKURAN` (`draf`, `diajukan`, `terverifikasi`) dan tabel perpindahan status `PERPINDAHAN` di `src/lib/pengukuran.ts`; aturan Semesteran hanya `diukurPadaBulan(frekuensi, bulan)` (`src/lib/indikator.ts`). Pengisi = Petugas Input Data/Kepala Unit dengan Unit di `aktor.unitIds`; pengisi Pengukuran = Pengguna yang terakhir menyimpan. Setiap perpindahan status (pengajuan maupun Verifikasi) lewat satu `pindahStatus` + `PERPINDAHAN`: dalam satu transaksi, baris Pengukuran dikunci `for("update")`, status asal diperiksa, lalu satu baris `riwayat_status_pengukuran` ditulis (waktu `clock_timestamp()`, jadi dua perpindahan dalam satu transaksi tetap berurutan). Penyimpanan mengunci baris Indikator `for("share")` sehingga bergiliran dengan perubahan Unit Pelapor. Bulan bawaan daftar = `bulanLalu()` (`src/lib/bulan.ts`). Halaman: `/pengukuran?unit=&bulan=` (daftar isian) dan `/pengukuran/isi?indikator=&unit=&bulan=`; status ditampilkan dengan `LabelStatus` (`src/app/pengukuran/status.tsx`). Draf yang dikembalikan Kepala Unit tetap Draf; penandanya `alasanPengembalian` (SQL di service Pengukuran, dipakai `daftarIsian` dan `pengukuranDikembalikan` untuk Dashboard pengisi), ditampilkan `LabelStatus dikembalikan` ("Draf · dikembalikan").
- Verifikasi: `verifikasiPengukuran`, `kembalikanPengukuran`, `bukaKembaliPengukuran` (hanya Kepala Unit dengan Unit di `aktor.unitIds`; alasan wajib untuk kembalikan dan buka kembali) = `ubahStatusPengukuran(aktor, id, aksi, alasan)` dengan `aksi` = kunci `PERPINDAHAN` selain `ajukan` (`AksiVerifikasi`; juga nilai tombol `aksi` form Verifikasi, aksi lain ditolak 400); status asal lain = 409. Bacaan: `antreanVerifikasi` (Kepala Unit, semua bulan), `ambilPengukuran` (detail + Riwayat Status; Unit sendiri, Komite Mutu, Admin Sistem; antrean dan detail sudah membawa `capaian`-nya), `statusPengukuranBulan` (Komite Mutu + Admin Sistem: semua Pengukuran bulan itu + baris `id`/`status` null untuk Unit Pelapor yang wajib tetapi belum mengisi, menurut aturan daftar isian). Halaman: `/pengukuran/[id]` (detail, satu-satunya tempat aksi Verifikasi; `/pengukuran/isi` mengalihkan Pengukuran non-Draf ke sini), `/pengukuran/verifikasi` (antrean), `/pengukuran/pantau?bulan=&unit=&status=` (saringan di halaman). Bagian tampilan bersama halaman Pengukuran (`LabelStatus`, `RiwayatStatus`, `AlasanPengembalian`, `pesanAtau`/`Pesan`, `kelasKartu`/`kelasInput`) ada di `src/app/pengukuran/status.tsx`.
- Capaian: satu-satunya tempat aturan perhitungan. Rumus murni di `src/lib/capaian.ts`: `hitungCapaian` (N × faktor / D, dikalikan dulu supaya Capaian yang sama dengan Target tidak meleset karena pembulatan; null bila D = 0), `capaianDari` (ΣN/ΣD, Kelengkapan, selisih, Status Capaian menurut Arah; dipakai untuk Capaian RS maupun Capaian Unit), `STATUS_CAPAIAN`/`LABEL_STATUS_CAPAIAN`, `formatCapaian`/`formatAngka`. Pembacaan + hak akses di `src/modules/capaian/service.ts`, hanya Pengukuran Terverifikasi dari Unit Pelapor yang aktif bulan itu: `trenCapaian(aktor, indikatorId, bulanAkhir)` untuk Monitoring (12 bulan, Semesteran hanya Juni/Desember; deret `rs` dan `unit[].titik` sejajar `bulan`, `kelengkapan.wajib` 0 = bukan Unit Pelapor bulan itu) dan `ringkasanCapaian(aktor, bulan)` untuk Dashboard (baris per Indikator aktif yang dinilai bulan itu + `jumlah`, `jumlahBelumLengkap` (Tercapai/Belum Tercapai yang Kelengkapan-nya belum penuh), `kelengkapan`, `belumTercapai`). Keduanya menolak bulan setelah bulan berjalan. Komite Mutu, Direktur, Admin Sistem: Capaian RS + semua Unit; Petugas Input Data dan Kepala Unit: hanya Unit di `aktor.unitIds` (`rs` null, ringkasan per Indikator + Unit). Halaman hanya menampilkan hasil service, tanpa menghitung sendiri (kecuali pratinjau langsung di form isian yang memakai `hitungCapaian`). Geser bulan dengan `geserBulan` (`src/lib/bulan.ts`). Halaman `/monitoring?indikator=&bulan=`; grafik dirender server tanpa pustaka (`src/app/monitoring/grafik.tsx`, lihat Tampilan), selalu disertai tabel. Tes ringkasan Capaian RS mencakup seluruh database tes bersama, jadi pakai tahun yang tidak dipakai tes lain.
- Dashboard = halaman `/?bulan=` (`src/app/page.tsx`), halaman pertama setelah masuk dan entri pertama `MENU`. Angkanya hanya dari `ringkasanCapaian(aktor, bulan?, sekarang?)` (tanpa bulan = `bulanLalu(sekarang)`, jadi bulan bawaan ditentukan service dan bisa dites); jumlah Pengukuran menunggu Verifikasi Kepala Unit = panjang `antreanVerifikasi(aktor)`. Bagian Perbaikan: daftar "Belum dianalisis" dari `belumDianalisis(aktor, bulan?, sekarang?)` (Lingkup RS untuk INM/IMP-RS, Lingkup Unit Pelapor untuk IMP-Unit; Petugas/Kepala Unit hanya IMP-Unit Unit-nya; tes memakai tahun 2018), jumlah Tindak Lanjut lewat tenggat dan PDSA berjalan = hasil `daftarTindakLanjut`/`daftarPdsa`. Lebar bilah di tampilan memakai CSS `calc()` dari angka service, bukan persentase hitungan halaman.
- Perbaikan (Rilis 2, spec `.scratch/rilis-2-pdsa/`): Analisis, Tindak Lanjut, dan PDSA di satu modul `src/modules/perbaikan/service.ts` (glosarium bagian Perbaikan). Lingkup = `unitId`, null = Lingkup RS. Hak akses hanya lewat `bolehBacaLingkup` (sama dengan `melihatCapaianRs`, ditambah Lingkup Unit di `aktor.unitIds`) dan `bolehTulisLingkup` (Komite Mutu/Admin Sistem semua Lingkup, Kepala Unit Lingkup Unit-nya); saringan query `saringLingkup`. Analisis unik per Indikator + Lingkup + bulan (`NULLS NOT DISTINCT`; `simpanAnalisis` = upsert, juga untuk mengubah), hanya selama bulan itu bisa dianalisis (`wajibBisaDianalisis`: Indikator aktif, sudah berjalan, sesuai Frekuensi, ada Unit Pelapor / Unit Lingkup adalah Unit Pelapor); IMP-Unit tanpa Lingkup RS (`punyaLingkupRs`, `src/lib/perbaikan.ts`). Analisis yang sudah ada selalu terbaca; `ambilAnalisis` membedakan `bolehTulis` (hak Lingkup, untuk Tindak Lanjut) dari `bolehTulisAnalisis` (juga bisa dianalisis). Nama Lingkup di tampilan hanya dari `labelLingkup`. Angka Capaian di halaman Perbaikan hanya dari `trenCapaian`. Halaman `/analisis?indikator=&unit=&bulan=` (alamat dari `tautanAnalisis`, `src/app/analisis/tautan.ts`), dibuka dari tabel Monitoring (`analisisTersedia`). `LabelCapaian` di `src/app/pengukuran/status.tsx`. Bantuan tes `unitPelapor` dan `terverifikasi` di `tests/bantuan.ts`.
- Tindak Lanjut selalu milik satu Analisis (`tambahTindakLanjut`; `ubahTindakLanjut` mengubah semua field termasuk status, catatan wajib saat Selesai/Dibatalkan; tidak ada hapus). Lewat tenggat hanya dari `lewatTenggat` (`src/lib/perbaikan.ts`) dengan `hariIni()` (`src/lib/bulan.ts`, zona waktu konfigurasi; `bulanBerjalan` turunannya; tanggal "YYYY-MM-DD" diperiksa `tanggalValid`, ditampilkan `labelTanggal`). Halaman dengan beberapa form memberi semua form `key` = versi data halaman (mis. `JSON.stringify` data yang diubah form-form itu), supaya setelah satu form berhasil pesan penolakan form lain hilang.
- Tanpa sesi, layout tidak merender tautan ke halaman terlindung (prefetch-nya dialihkan proxy dan meninggalkan alamat `/masuk?_rsc=...` saat Back).
- Cek sebelum selesai: `npm run check` (typecheck + lint + tes).
- Dev: `cp .env.example .env`, database dev = container `mutu-rs-db` (127.0.0.1:55434, user/sandi/db `mutu`), lalu `npx next dev -p <port>` (port 3000 sering terpakai). Buka lewat `http://localhost:<port>`: dari `127.0.0.1` dev server memblokir JS-nya, sehingga komponen client tidak berjalan. Deploy: `docker compose up -d --build` (membaca `.env`).
